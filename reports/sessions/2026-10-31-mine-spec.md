## Contradictions and gaps found

1. **Unpaid miner budget** (ADR-044 "an epoch with no claims burns the miner share"; integer-division remainder "burned"). The node never pays it, so it stays in the keyless `MINING_RESERVE`. Nothing is minted and nothing reaches anyone, so it is economically out of circulation, but it is not a burn in the ledger and it is not carried into a later epoch's reward either. The spec does not pick one; listed as an open question in spec/09-mining.md. Not changed (consensus).
2. **Cap wording**. ADR-044 says "emission stops at the cap; total minted checked with `check_supply`". ADR-068 superseded it with a funded reserve; the mining path has no `check_supply`. The node matches ADR-068 (genesis reserve >= initial reward, and >= lifetime emission when tail > 0, genesis.rs ~934). ADR-044 text is stale; no code change.
3. Not vectorized (state-level, listed in Gaps): share admission (`apply_mining_share` order: epoch 0, wrong epoch, budget spent, block cap, already paid, DAG PoW); epoch boundary height; reserve payout cap (`pay_from_reserve`); genesis funding check. Covered by existing node tests (crates/node/tests/mining_rewards_tests.rs), not replayed from vectors.

No other contradiction found between ADR-044/068 and the code for the rules above.
