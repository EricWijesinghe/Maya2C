# 2026-11-21 — wasmtime 48.0.8 -> 48.0.10 (RUSTSEC-2026-0566..0573)

Windows 11 (10.0.29708), `nightly-2026-07-15`, debug test profile, one machine.
Every command ran through `cargo-slot.sh`.

## Why

`cargo deny check advisories` on master failed on RUSTSEC-2026-0566..0573,
all fixed in wasmtime 48.0.9. 48.0.10 (2026-11-19) adds one more fix
(RUSTSEC-2026-0587), in `wasmtime-wasi` on Windows, which the VM does not link.

## Release notes (48.0.9, 48.0.10)

Read from `gh api repos/bytecodealliance/wasmtime/releases/tags/v48.0.9` and
`v48.0.10`. Every entry is a security fix in `wasmtime-wasi`,
`wasmtime-wasi-http`, the component model, the GC heap, builds without
`threads`/`gc`, or `Caller::get_module_export`. **None touches fuel, Cranelift
codegen or Pulley.**

## Gas evidence

`crates/vm/tests/gas_golden_tests.rs` is new. It was recorded on 48.0.8 and
covers seven modules: empty, i64 loop, calls/recursion, br_table/select/globals,
memory and bulk ops, NaN-canonicalised floats, and host storage/events. For
each module it pins the gas used, the smallest sufficient gas limit, and the
output.
