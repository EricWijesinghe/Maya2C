## In plain words

**maya-testnet-1** is a practice notebook. Everyone can write in it, and the
coins in it are **play money**. Nothing you do here is worth anything.

It is practice for the real thing, so you can see how it feels: make a wallet, get
some play coins, send them to a friend, and watch the notebook record it. Every
note is signed with two different post-quantum locks, and the notebook checks
both.

The last run: **7 days 15 hours 42 minutes with zero halts** (a halt is any gap
over 60 s; 661,357 s, blocks 0 → 393,812, genesis 2026-10-20 15:54 UTC), stopped
on purpose at **2026-10-28 07:36 UTC**. Two caveats were recorded with it: one
validator held 71% of stake, so it finalized alone, and the run was on the
pre-mining build. Evidence:
[stop report](https://github.com/EricWijesinghe/Maya2C/blob/master/reports/sessions/2026-10-28-testnet-stopped.md).

:::caution[Test coins only]
Testnet coins have **no value** and cannot be bought or sold. Anyone offering to
sell you Maya2C coins is not selling anything this project issued. The network may
be reset, and the software has not had an independent security audit. Do not use
it to protect anything that matters.
:::

## 1. Get a wallet

**Command line**, from the release that ships `l1-wallet`:

```bash
l1-wallet --keystore my.key generate      # encrypts the new key with your password
l1-wallet --keystore my.key address       # prints your 64-hex-character address
```

The keystore is encrypted with Argon2id and ChaCha20-Poly1305 (see
[wallet integration](/guides/wallet/)). Check release downloads against
`SHA256SUMS` on the same release page. The desktop installers are not code-signed
yet, so Windows and macOS warn about an unknown publisher.

The faucet limits requests **per address and per IP** over a 24-hour window
(`apps/faucet/src/limit.rs`). Its code defaults are 1,000 base units per grant
(`MAYA_FAUCET_DISPENSE`) and 1,000,000 base units per day (`MAYA_FAUCET_DAILY_CAP`,
`apps/faucet/src/main.rs`). The operator sets the live values, which the status
page shows while the testnet runs.

The same request from a terminal:

```bash
curl -X POST https://faucet.maya2c.dev/request \
  -H 'content-type: application/json' \
  -d '{"address":"<your address>"}'
```

A `429` response says which limit was hit: `rate_limited_ip` or
`rate_limited_address`. Back off, and wait for the window.

Each transfer is about 13 KB, because it carries two post-quantum signatures, and
the fee is charged per byte. The fee rule and the minimum are in
[how a transaction works](/guides/transactions/).

- **Four validators, run by the project.** The committee is not yet independent.
  Open registration is reviewed, for the reason in
  [run a validator](/guides/validators/).
- **Resets happen.** Earlier chains halted or were restarted: a difficulty-retarget bug that
  saturated total work and halted the chain was fixed in ADR-035, and ADR-036 made every signature commit
  to the genesis, so a transfer for this testnet cannot be replayed elsewhere. ADR-046
  changed amounts to 256 bits. Balances from one chain do not exist on the next.
- **Testnet mining pays nothing:** testnet coins have no value. Mainnet rewards are on [mining and validators](/guides/mining/).

## What a testnet can and cannot show

A testnet produces **observations**. It does not produce a security proof.

- **Liveness** is observable: the fraction of rounds that commit an anchor, over
  a window $T$, is $\hat{\lambda} = \#\{\text{committed anchors in } T\} / \#\{\text{anchor slots in } T\}$.
  A figure is only meaningful with its window, its commit and its hardware.
- **Safety** is not observable by watching a single chain. It rests on the quorum
  argument in [consensus](/guides/consensus/): two honest nodes that disagree on
  a committed block would contradict $q = n - f$ and $n - 2f \ge f + 1$.
- **The halting condition** from [run a validator](/guides/validators/) predicts
  when a testnet stops. With $m$ online seats and $k$ absent, it halts when
  $k > \lfloor (m+k-1)/3 \rfloor$. A testnet with four seats tolerates one absent
  seat and no more.

## What a claim needs

The repository's standing orders require that every performance figure carry
its commit, hardware, OS, kernel and the exact command. A testnet figure follows
the same rule. There is no `cargo xtask bench` yet, so measured figures are
recorded by hand in the reports, and the status page is the live record.

Interval estimates for $\hat{\lambda}$ need a model of arrivals. For a binomial
count of $X$ successes in $N$ slots, the normal approximation gives

$$
\hat{\lambda} \pm z_{1-\alpha/2}\sqrt{\frac{\hat{\lambda}(1-\hat{\lambda})}{N}}.
$$

The approximation is poor for small $N$ or $\hat{\lambda}$ near 0 or 1. A short run
on a small committee is an anecdote, and this page treats it as one.
