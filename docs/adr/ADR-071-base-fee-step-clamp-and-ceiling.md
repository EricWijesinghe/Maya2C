# ADR-071: the base fee rises at most one denominator's share per block, and has a ceiling

- Status: Proposed. The mechanism is implemented; the ceiling value is a placeholder **pending Eric's economics decision** (see Options).
- Scope: consensus (fee market, state root). Rides mainnet genesis. Not for any network where fees are already active without a re-genesis.
- Number: the brief named ADR-069, but `docs/adr/ADR-069-post-mainnet-feature-program.md` already exists (and ADR-070 is committee floor). Numbers are not reused, so this is ADR-071.
- Spec: `spec/04-fees.md` FEE-3 (rewritten), FEE-6 (new). Vectors: `spec/tests/fees.json` (generated by `crates/spec-ref/src/bin/spec-vectors.rs`).

## Context

The live base-fee rule is the linear `next_base_fee` in `crates/fee-market/src/base_fee.rs`, called from the node by `FeeRecord::next` in `crates/node/src/state/fees.rs` (once per block, from `settle_fees` in `crates/node/src/state/fee_exec.rs`). The neural rule (`neural_next_base_fee`, `FeeRule::Neural`) is not called by the node (`rg` finds it only in `crates/fee-market` and `bins/neural-gas-trainer`); it is RESEARCH and dark.

The step is `delta = parent × |size − target| / target / denominator`, with no upper bound on `|size − target|`. A block at `k` times the target moves the fee by `1 + (k−1)/denominator` in one step.

## Decision

1. **Rise clamp (FEE-3).** A rising block raises the fee by `min(max(delta, 1), max(parent / denominator, 1))`. The `max(·, 1)` on each side is EIP-1559's and is kept. The documented "1/8 per block" is now true for every block size.
2. **Ceiling (FEE-6).** `limits::MAX_BASE_FEE_PER_BYTE` is compiled in next to `MIN_BASE_FEE_FLOOR`. A rise ends at `min(parent + rise, max(MAX_BASE_FEE_PER_BYTE, parent))`. A fee already above the ceiling holds; it does not fall to meet it, and a rise never lifts it further.
3. **Validation.** `FeeConfig::validate` rejects `initial_base_fee > MAX_BASE_FEE_PER_BYTE` with `ConfigError::Ceiling`. The floor is at most the initial fee, so it is covered too. Genesis calls `validate` (`crates/node/src/genesis.rs`, `FeesGenesis::record`), so an over-ceiling genesis fails to load.
4. **The fall is unchanged.** `parent_size ≥ 0` keeps the gap at most `target`, so the fall is already at most `parent / denominator`. No clamp is needed there.
5. **Neural rule.** `neural_next_base_fee` gets the same share and ceiling, so the unit-gain-equals-linear invariant holds. It is dark, so this is for consistency, not a live change.

Limits of this decision: the clamp bounds the fee's rate. It does not bound block size, so an attacker who can fill sub-DAGs still pays the (now bounded) fee for every byte. The ceiling bounds the price, not the spam.

## Options for the ceiling (economics: Eric)

Standard transfer `S = 13,215 B`, 24 decimals (`1 MAYA = 10^24` base units). Per-byte value is `⌊units / S⌋`, so the cost at the cap is at most the stated amount.

| Option | Cost of one standard transfer at the cap | `MAX_BASE_FEE_PER_BYTE` (base units per byte) | Share of a 1-coin balance a transfer can take at the cap |
|---|---|---|---|
| A | 0.01 MAYA | 756,715,853,197,124,479 | 1% |
| **B (default, pending Eric)** | **0.1 MAYA** | **7,567,158,531,971,244,797** | **10%** |
| C | 1 MAYA | 75,671,585,319,712,447,975 | 100% |

- Option B is the middle option and is the value in `limits.rs`. The constant is written as `Amount::from_u128` because option C does not fit in `u64`.
- Option C lets a full-block attacker price a 1-coin account out of transferring at all (the cap cost equals one whole coin, so the 1-coin test passes only by rounding). Option A is the most conservative for users and the easiest to hit at high demand.
- The ceiling is a consensus value. Changing it later is a fork, so it must be right before genesis.

## Consequences

- Recovery is slow: from 10 to the B cap takes about 354 full blocks (computed from the new step), against about 19 under the old rule. That is the intended effect of the clamp and is also a cost to the chain: a real demand spike is priced slowly.
- Consensus change. Any network that has the fee market active computes different base fees, and so different state roots, after this change. It rides mainnet genesis. No live network is changed by this PR.
- The Z3 model in `formal/z3/fee_market.py` now models the clamp and proves FEE-6. Z3 is not installed on this machine, so the proofs are NOT VERIFIED here.
- The Kani harness `a_rise_is_one_denominator_share_and_stops_at_the_ceiling` (`crates/fee-market/src/proofs.rs`) is written but NOT VERIFIED: Kani runs in WSL only.
- Two reviewers are required for a consensus change (`CLAUDE.md`, Production Standing Orders). This is not enforced by CI.
