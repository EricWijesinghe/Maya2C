# Mainnet genesis inputs

Public inputs for `genesis-ceremony`. The keys are not here: each validator key and
council key is generated by its holder on their own machine
(`docs/runbooks/regenesis-checklist.md` §2), and neither Claude session holds one.

## `mining.json` (ADR-044, ADR-068, DECISIONS 2026-10-29)

| Field | Value | Meaning |
|---|---|---|
| `initial_epoch_reward` | 299452429842573579739904175 | about 299.45 coins an epoch: half of 21M before the first halving |
| `halving_epochs` | 35064 | about 4 years at one block a second and 3,600-block epochs |
| `tail_epoch_reward` | 23956194387405886379192334 | about 23.96 coins an epoch, 1% of 21M a year, paid forever |
| `miner_share_bps` | 7000 | 70% to miners, 30% to the committee |
| `target_shares` / `max_shares_per_block` | 1000 / 16 | 16 × 3,600 ≥ 4 × 1,000, so the ×4 retarget can harden fully |
| `initial_target` | `0000ff…` | an opening share target; the per-epoch retarget (at most ×4) finds the real rate |
| `dag` | `mainnet` | the 4 GiB dataset |

If the mainnet block rate is not about one block a second, recompute `halving_epochs` and
`tail_epoch_reward` before signing.

## The reserve

Rewards are never minted. They are paid from a keyless reserve that genesis funds with the
schedule's exact lifetime emission (`MiningRecord::lifetime_emission`, to the last `u64`
height):

```
--mining-reserve 122753829695359067419575633036805965021648
```

That is about 1.23 × 10^17 coins (about 2^136.5 base units), under the 2^192 ceiling. The tool
refuses any less.

## The command (run on genesis day, after the keys exist)

```
genesis-ceremony --chain-id maya-mainnet \
  --supply <ROOT UNITS> \
  --validators validators.txt \
  --mining deploy/genesis/mainnet/mining.json \
  --mining-reserve 122753829695359067419575633036805965021648 \
  --council council-public --council-threshold 2 --council-max-pause-blocks <N> \
  --min-self-bond <UNITS> --min-delegation <UNITS> \
  --timestamp <UNIX> --out-dir out
cargo xtask genesis-check out/genesis.json
```

- `validators.txt`: one line per validator, `label key operator bond`, with at least 7
  validators and no operator above 20% of the bonded stake.
- The check counts payout addresses. At launch every validator is run by one person
  (DECISIONS 2026-10-25), so each gets its own operator address. The launch says so publicly:
  "validators run by one operator", never "independent".
- For `maya-mainnet` the tool adds what the chain needs on its own:
  - stake-weighted voting (ADR-040);
  - a refusal to run without the council (ADR-050);
  - the fee market with `min_base_fee` = 10^6 (S-007).
- `--min-self-bond` and `--min-delegation` are required on `maya-mainnet`. The devnet
  defaults are 10^-21 and 10^-23 of a coin. Mainnet: 1,000 coins
  (`1000000000000000000000000000`) and 1 coin (`1000000000000000000000000`), decided
  2026-10-30 (DECISIONS.md).
- `genesis-check` refuses a file with any of these: no fees, a lower fee floor, no mining
  and no block difficulty, fewer than 7 validators, an operator above the cap, or staking
  floors below the mainnet constants in `xtask/src/genesis_check.rs`.

## Dry run (2026-10-30, throwaway keys, nothing published)

Inputs: 7 throwaway validator keys, 3 throwaway council keys, and the values above. Results:

- The ceremony wrote the genesis, with total supply 122753829695429068419575633036805965021648 units.
- `cargo xtask genesis-check`: **PASS**. Fees were 1000000/1000000, stake-weighted, council 2-of-3.
- `maya2c-node` booted from it as `validator 0 of 7` on `maya-mainnet`, with genesis id `28210c54…`. That id is not mainnet's: the real keys and timestamp change it.

Signing the real genesis is **APPROVED: sign genesis**, a separate approval from the re-genesis.
